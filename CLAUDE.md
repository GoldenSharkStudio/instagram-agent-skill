# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code plugin (`.claude-plugin/plugin.json` + `marketplace.json`) that ships 14 skills under `skills/ig-*/`. Each skill is a `SKILL.md` (frontmatter `name` + `description`, the description is the trigger text). The description holds triggers only, English then Portuguese in the same text ("Use when …" then "Use quando …", ≤1024 chars), with no summary of the workflow and no numbers; `tests/test_descriptions.py` enforces it. Four of them (`ig-reel`, `ig-caption`, `ig-human`, `ig-viral`) ship Python CLI tools, six scripts in all; `ig-profile` ships only JSON data, `ig-setup` its own copies of the two `templates/voice.*.md` forms (kept equal by `tests/test_templates.py`). There is no build, no package manager, no dependencies, no linter config. Tools are stdlib-only Python 3 and must stay that way (the README promises "no dependencies, no network").

Users install by copying `skills/ig-*` into `~/.claude/skills/`, or by pasting a single `SKILL.md` into a chat. So **every skill folder must work on its own**, and a SKILL.md must still make sense without its scripts.

## Running the tools

Every tool reads a file path or `-` / stdin, and supports `--json`. Run from anywhere; data files are resolved relative to the script (`HERE = os.path.dirname(__file__)`).

```bash
python3 skills/ig-reel/hookscore.py hooks.txt          # one hook per line; or --hook "..."
python3 skills/ig-reel/beats.py script.txt --target 30 [--wpm 165]
python3 skills/ig-caption/caption.py caption.txt --keywords "a,b" [--truncate 125]
python3 skills/ig-human/humanize.py draft.txt --report [-o out.txt] [--lexicon slop.en.json]
python3 skills/ig-human/detect.py draft.txt [after.txt]  # second arg = before/after delta
python3 skills/ig-viral/swipe.py captured.tsv [--out swipe.md] [--hooks path/to/hooks.json]
```

Every tool also takes `--lang {en,pt-BR,auto}`, default `en`. `auto` counts the `auto.stopwords` of each language file present, writes its pick to stderr (`lang: auto -> en (3 vs 0)`) and falls to `en` on a tie. A language with no file is exit 2 naming the file (fail closed; e.g. `pt-BR` in a lone copy of `ig-human` without its `slop.pt-BR.json`). `--lexicon` wins over `--lang`. The SKILL.md files run every script with `--lang {language}`, taken from the **Language:** line of `voice.md` (missing = `en`); `tests/test_skill_lang.py` finds every command in them, requires the flag and runs each as written. Every SKILL.md opens with the same "Before you write" block, copied between `<!-- shared:before-you-write -->` markers: read `voice.md`, answer in its language, what `{language}` and `{skill_dir}` mean; commands are written `python3 {skill_dir}/name.py` (the skill's base directory, not the cwd). `tests/test_shared_block.py` keeps the 14 copies byte-equal, the block before any other section, and every command prefixed. A skill's own steps go after the block, never inside it.

Exit codes are meaningful (skills use them as verdicts): `hookscore` exits 1 if the best hook scores < 70; `caption` exits 1 unless verdict is `READY`; `detect` exits 1 unless the last result is `PASS`; `2` means bad input: a file that cannot be read or written (missing, a folder, not UTF-8, an explicit `--hooks` or `--lexicon` that does not load) is exit 2 naming the path, never a traceback (`tests/test_input_errors.py` derives the path arguments from each argparse). Only swipe's default `../ig-reel/hooks.json` degrades instead, so `ig-viral` still runs alone. The exit code is the same with `--json`. `humanize --report` writes the report to stderr and the cleaned text to stdout.

## Tests

```bash
python3 -m unittest discover tests          # whole suite, stdlib unittest
python3 -m unittest discover tests -p "test_caption.py"   # one file
```

Run from the repo root. Golden tests pin the numbers in the README example blocks, and `test_invariants.ReadmeBlocksAreRealOutput` checks those README lines verbatim against real tool output on the inputs in `tests/fixtures/`. So when a tool's output changes, update the README block and the pinned values together. Invariant tests also derive the prose counts from the JSONs, check that duplicated regexes have not drifted, that each tool folder runs from a lone copy, and that every import is stdlib. A test marked `expectedFailure` is a known bug logged for a later phase, not a broken test.

Trigger evals live in `evals/`: `prompts.json` holds 3 English and 3 Portuguese prompts per skill, `python3 evals/build.py` writes one case per prompt (`evals/<skill>-<en|pt>-<n>/`, graders: the skill fires, no other `ig-*` skill does). `tests/test_evals.py` keeps the cases equal to the table, requires every skill in it, and runs the grader regexes against all skill names. A prompt that mentions pasted text must carry the text, or Claude asks for it instead of loading the skill. Running them spends model usage, so it is not part of the suite:

```bash
claude plugin eval . --ablation none --runs 1 -j 4 --no-publish --trust-plugin --json out.json
```


## Architecture and coupling

- **Data vs. logic.** Tunable content lives in JSON, meant to be edited by users: `ig-human/slop.en.json` (lexicon + replacements, invisible-char classes, typography substitutions, structural tells, voice regexes, splice connectives, conjunctions that go with a deleted phrase, and `inflection`: every inflected form is its own entry with its own replacement and an `of` naming its base; `tests/test_inflection.py` derives the forms each verb/noun should have from the suffix rules and fails on a missing one or an undeclared exemption; `slop.pt-BR.json` is a skeleton, empty `words`/`phrases` and `"calibrated": false`: `detect` reads that flag, absent = `true`, and caps the verdict at REVIEW with its own line and `"calibrated"` in `--json` until a corpus fills the lexicon), `ig-reel/lang/en.json` and `ig-caption/lang/en.json` (every word list and language-bound regex the scripts use, the thousands separator included; `tests/test_lang.py` fails if one is hardcoded in Python; each caption ask carries an `id`, the same in every language: the `--json` `ask_ids` is what a program reads, `asks` holds the names and translates; each has a `pt-BR.json` beside it, as does `ig-viral/lang/` (which also holds `swipe.cta`, the patterns that mark a captured hook as a call to action; `tests/test_swipe_cta.py`), checked by `tests/test_pt_br.py`: the README hooks translated land in the same band, and the `--lang` nets copy a folder without its shipped pt-BR so they test only what they plant), and the sentences each tool prints: they live in `messages` of its `lang/<code>.json` (a section of `ig-reel/lang/en.json` and `ig-caption/lang/en.json`; the new files `ig-human/lang/en.json` and `ig-viral/lang/en.json`, kept apart from `slop.en.json` so `--lexicon` never swaps them), as `str.format` templates with named fields, read through the `say(M, key, **kw)` copy in each script. `tests/test_messages.py` fails on a phrase left in Python, a missing or dead key, or fields that do not match the call. `ig-reel/hooks.json` (30 formulas, each with a `match` regex per language, `{"en": ..., "pt-BR": ...}`: swipe uses only the slot of `--lang`, an empty or missing slot never matches, an unknown language key is a broken schema; `tests/test_hooks_lang.py`), `ig-profile/rubric.json` (12-item, 100-point score, read by the model, not by code). Prefer changing the JSON over hardcoding in Python.
- **`humanize.py` fixes, `detect.py` scores.** Both read `slop.en.json`. humanize applies three passes (invisible chars → typography → lexicon) and only *flags* structural tells (they need human rewriting, not regex); detect therefore caps the verdict at REVIEW while any tell is left. Both build a lexicon entry's regex with the same `term_re` (a test keeps the copies equal). Lowercase-only voices are deliberately preserved when restoring capitals after a deleted opener. The cleanup after a deletion and the restored capital touch only the lines a deletion changed; the dash pass decides its comma at the dash. Text no pass changed comes back byte-equal (`tests/test_untouched.py`, a clean corpus per `slop.*.json`, plus a declared list of every case-raising call).
- **Cross-skill dependency:** `ig-viral/swipe.py` reads `../ig-reel/hooks.json` and optionally imports `hookscore.run` from `../ig-reel` via `sys.path`. Both are wrapped so swipe degrades gracefully if `ig-viral` is copied alone — keep it that way. Changing `hookscore.run`'s signature or `hooks.json`'s schema affects swipe.
- **Duplicated regexes.** `WORD_RE`, `EMOJI_RE`, etc. are copied across scripts on purpose (each folder is standalone). When fixing one, check the sibling copies in the other scripts. What counts as concrete (a figure with its unit or price, "23h", a month, a spoken number, a money word, a name inside a sentence, an acronym on a line that is not shouting) is one pair of functions, `build_concrete` + `concrete_marks`, copied into hookscore, beats, caption and detect, fed by the `concrete` section of each folder's `lang/<code>.json` (equal across folders). `tests/test_concrete.py` keeps the copies and sections equal, runs the same phrases through each tool's own verdict per language, and fails on a concreteness regex anywhere else. Same for the two link regexes, caption `LINK_RE` (counts) and humanize `URL_RE` (shields from rewrites): `tests/test_links.py` finds every regex holding `https?://` and runs the same links through each, bare `loja.com.br/x` included. Same for `APOSTROPHES` (`’`/`‘` → `'` on the copy that is matched, never on the user's text; humanize gets it from its typographic pass instead): `tests/test_apostrophe.py` runs every data string holding a `'` through every tool that reads it. Input is composed to NFC at every public entry (`run`/`analyse`/`humanize`/`classify`/`count_tells`), since an NFD accent splits words in `re`; files are read through one `read_text` copied into each script. `tests/test_io.py` runs every tool on NFC and NFD text and asks for the same output, keeps the `read_text` copies equal and fails on an `open()` outside a `with`.
- **Shared user state** lives outside the repo in `~/.claude/instagram/`: `voice.md` (from `templates/voice.en.md` or `voice.pt-BR.md`, read by every skill), `swipe.md` (written by `/ig-viral`, read by `/ig-reel` and `/ig-plan`), `log.md` (appended on post approval, read by `/ig-plan`, `/ig-comment`, `/ig-audit`; its line is defined in `templates/log.md` and copied between `<!-- shared:log-schema -->` markers into each SKILL.md that names it, kept equal by `tests/test_templates.py`), `plan.md` (written by `/ig-plan`).

## Product invariants (stated in the README; don't violate them in skills or code)

- Nothing posts to Instagram. Every skill ends with a copy-ready block and an explicit user approval. No browser automation, scraping, login, or third-party posting tools.
- Never fabricate metrics, clients or outcomes; a missing number becomes `{{your number}}` plus a flag.
- The detection checks are local heuristics; never claim they are GPTZero/Originality/etc. or "undetectable".
- Platform constants go stale (e.g. `HASHTAG_LIMIT = 5` in `caption.py`, changed 18 Dec 2025). When changing one, update the comment's date and the README/SKILL.md mentions too.
- Counts are quoted in prose ("240 terms", "30 formulas", "14 skills", "18 invisible classes"). Adding to the JSON means updating those numbers in `README.md`, the SKILL.md files and `plugin.json`'s description.
